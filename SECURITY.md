# Security policy

Salt TUI can display Salt output and invoke Salt commands. Reports involving command execution, target selection, secrets in logs or diagnostics, and unsafe state application are especially helpful.

## Supported versions

Security fixes are considered for the latest published version and the current `main` branch. Older releases may be assessed case by case; there is no guarantee of backports.

## Reporting a vulnerability

**Maintainer action before publishing this file:** Enable [private vulnerability reporting](https://github.com/pratik-anurag/salt-tui/settings/security_analysis) and verify the [private report form](https://github.com/pratik-anurag/salt-tui/security/advisories/new) works, or replace this paragraph with a private maintainer contact. Private vulnerability reporting is currently disabled.

Please do not file a public issue or pull request with exploit details before a private reporting route is available. In a private report, include the affected version, impact, reproduction steps, and a minimal proof of concept. Remove credentials, tokens, and identifying Salt data. If you know a mitigation, include it.

The maintainer will acknowledge and assess reports, coordinate a fix and disclosure with the reporter where practical, and publish an advisory when appropriate. No fixed response or remediation time is promised.
